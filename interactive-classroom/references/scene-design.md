# Scene Design Reference 

## Scene sequencing

A common full lesson arc:

1. Orientation
2. Diagnostic / prediction
3. Core concept
4. Dialogue or Socratic interaction
5. Typed interactive widget when representation/manipulation matters
6. Worked example, simulation, code/data/equation/procedure practice as appropriate
7. Application / PBL
8. Mastery check
9. Reflection + next steps

Do not force all scene types into every course.

## Orientation

Include:

- observable outcomes;
- scope;
- prerequisite assumptions;
- how interaction works;
- offline/runtime note.

## Concept

Use a concise explanation plus one concrete example/contrast. Prefer a whiteboard or graph only when spatial relationships add meaning.

## Discussion

1. Present a debatable/ambiguous claim.
2. Ask learner to commit first.
3. Reveal 2–4 pre-generated viewpoints.
4. Let learner inspect evidence/assumptions.
5. Show synthesis and unresolved uncertainty.

Avoid theatrical dialogue that adds no reasoning.

## Socratic

Use one central question and a hint ladder. Wrong answers branch to targeted remediation, then retry.

## Whiteboard

Use for causal structure, mechanism, workflow, decomposition, or worked derivation. Provide a text fallback.

## Knowledge graph

Use when the learner benefits from exploring relationships among concepts. Dragging is optional exploration, never a prerequisite for comprehension.

## Timeline

Use for chronology or ordered process evolution. Do not fake a timeline for unordered categories.

## Simulation

Must include:

- prediction/question;
- variables + ranges/units;
- visible output change;
- assumptions;
- guided experiment;
- interpretation.

A simulation without a learning prompt is a toy.

## Quiz

Each item should contain objective ID, prompt, response model, correct rule, misconception feedback and retry/remediation behavior. Prefer 3–7 high-value questions.

## PBL

Minimum:

- learner role;
- authentic problem;
- constraints/resources;
- 2–5 meaningful decisions;
- visible state variables and effects;
- milestone;
- debrief.

Consequences must be deterministic and inspectable.

## Reflection

Useful prompts:

- “哪个结论最容易被误解？为什么？”
- “如果一个关键假设改变，结论如何变化？”
- “用三句话向同学解释本节内容。”

## Navigation

Prefer stepper/navigation + previous/next + free revisit. Do not lock prior scenes unless explicitly requested.


## typed interactive planning

Choose the widget type at outline time, then load the matching `references/widgets/*.md`. The widget type is driven by the learning objective and discipline profile, not by novelty.
